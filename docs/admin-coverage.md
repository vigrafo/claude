# Admin-Backend – Abdeckung

Stand: Implementierung im Branch `claude/kind-gauss-d3bemj`. Alle Seiten liegen unter `src/app/admin/(panel)/…`
(Anmeldung/Re-Auth ohne Guard unter `src/app/admin/(auth)/…`). Server Actions in `src/app/actions/admin/*.ts`,
testbare Fachlogik in `src/server/admin/*.ts`.

**Querschnitt (gilt für alle Zeilen):**
- Jede Seite: `adminGuard(recht)` = IP-Allowlist (`ADMIN_ALLOWED_IPS`) + `requireAdmin(recht)` (eigenes Cookie, MFA-Pflicht).
- Jede Action: `adminAct(recht, …)` (Guard + Fehlerbehandlung) **und** erneute Rechteprüfung im Service (`assertPerm`, Default deny).
- Jede Mutation schreibt `audit()` (hashverkettet, ohne sensible Inhalte).
- Listen: `?q=` + `?page=` (25 je Seite), Tabellen in `.table-wrap`, Leerzustände.
- Re-Auth (TOTP, `REAUTH_MINUTES`): Secrets & Moduswechsel Zahlungsanbieter, CSV-Export, Rollenvergabe/-entzug, Freigaben (Vier-Augen), Tokenkorrekturen > 100.
- Kein Impersonation-Feature, keine Shell-Ausführung, kein Restore-Button.

## Bekannte Lücken / Abhängigkeiten außerhalb des Admin-Bereichs
- `fulfil()`/`issueInvoice()` in `src/server/payments/service.ts` sind nicht exportiert → manuelle Banküberweisung erzeugt keine Rechnung.
- Zahlungsadapter lesen Zugangsdaten aus ENV; das im Backend hinterlegte (verschlüsselte) Secret wird noch nicht verwendet.
- Abruf temporärer Verifizierungsbelege (`tempEvidenceKey`) ist nicht angebunden.
- Geplante Gold-Inhalte (`scheduled`) werden nicht automatisch auf `published` gesetzt.
